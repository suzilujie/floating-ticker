悬浮行情 App（BTC · iOS）概念文档

持续追加型文档 ｜ 最后更新 2026-09-17 ｜ 记录讨论中产生的概念、术语、决策与背景

本文档记录概念与术语（轻量、持续追加）。完整方案、架构、接口与实现细节见 docs/设计文档.html。

一、平台能力类概念

画中画悬浮窗 (Picture-in-Picture Overlay)

定义借助 iOS 系统级画中画（PiP）能力形成的悬浮窗口，可置顶于桌面与任意 App 之上，由系统托管窗口生命周期与控件。
产生背景iOS 禁止第三方 App 在其他 App 之上绘制任意视图（无 Android 的 SYSTEM_ALERT_WINDOW 权限），PiP 是唯一合法的全局悬浮途径。
关键特征系统强制显示关闭与还原控件；窗口尺寸受系统控制（约三档）；必须跟随"视频播放"语义。
状态已采纳作为本项目的核心实现基础
关联概念帧源层（AVSampleBufferDisplayLayer）、帧泵（Frame Pump）、灵动岛（Live Activity）

帧源层 (Sample Buffer Display Layer)

定义AVSampleBufferDisplayLayer：可直接投放 CMSampleBuffer 视频帧的渲染层，不依赖视频文件或播放器。
产生背景PiP 只接受两类内容源：AVPlayerLayer（只能播固定媒体）与 AVSampleBufferDisplayLayer（可自定义帧）。要把行情"画"成视频，必须用后者。
状态已采纳
关联概念帧泵、像素缓冲（CVPixelBuffer）、画中画悬浮窗

帧泵 (Frame Pump)

定义驱动 CVPixelBuffer 持续产出并投喂给渲染层的调度机制，本项目采用自适应帧率：价格变化时立即出帧，静止时降到 1 fps 心跳保活（keep-alive）。
产生背景PiP 要求持续有帧输入才能维持画面；但同时，持续高频出帧是主要耗电点。行情数据是稀疏事件（1Hz），无需恒定 60fps。
备选CADisplayLink 固定 30/60fps（耗电）、定时器驱动（时序精度略差）
状态已采纳
关联概念帧源层、等宽数字防抖

灵动岛 / 实时活动 (Dynamic Island / Live Activity)

定义基于 ActivityKit 的锁屏与灵动岛常驻展示能力，iOS 16.1+，能显示实时状态。
产生背景最初评估的候选方案之一（B 方案）。
局限仅显示在顶部胶囊区，无法任意位置悬浮；后台刷新必须依赖服务端 APNs 远程推送，而推送能力需付费开发者账号。
状态暂缓第一版不做，作为可选补充
关联概念画中画悬浮窗、免费个人团队、APNs

二、网络与数据源类概念

SNI 阻断 (SNI-based Blocking)

定义在 TLS 握手的明文阶段（Server Name Indication，SNI）识别目标域名并中断连接。表现为 TCP 层可连通、TLS 层超时。
产生背景探测中发现 Gate、Bitget、CoinEx WS 等均"端口通但请求超时"，属典型 SNI 阻断特征。
意义解释"为什么能 ping 通却拉不到数据"，避免误判为对方服务故障。
状态已识别作为数据源评估的关键判据
关联概念DNS 污染、公共数据域、系统代理透传

DNS 污染 (DNS Poisoning)

定义域名解析被返回无效或伪造地址。本项目实测中 www.okx.com 被解析为 169.254.0.2（链路本地保留地址，不可路由）。
产生背景首轮探测中多次出现返回 Meta / Dropbox 等无关 IP 的现象。
状态已识别
关联概念SNI 阻断

公共数据域 (Public Market Data Domain)

定义交易所提供的、无需 API Key 的公开行情数据专属域名。本项目指 Binance 的 *.binance.vision（走 AWS CloudFront）。
产生背景主站域名（api.binance.com / stream.binance.com）在国内直连被阻断，但公共数据域直连可达。
实测WS 60 秒压测：61 tick、平均间隔 989ms、最大间隔 1010ms（零断流）；REST 10/10 成功、平均 121ms。
状态已采纳作为 L1 主源与 L2 兜底
关联概念分层容错、异构兜底、SNI 阻断

分层容错 / 多源热备 (Tiered Failover)

定义按优先级排列多个数据源，前一层不可用时自动降级到下一层，上层恢复后回切（prefer-higher-tier）。
产生背景用户明确要求"需要稳定兜底"；单一源在国内网络环境下不可靠。
层级L1 WS 主源 → L2 同域 REST 轮询 → L3 异构 REST → L4 代理模式备选 → L5 自建中继
状态已采纳
关联概念健康检查器、指数退避、异构兜底

异构兜底 (Heterogeneous Fallback)

定义兜底源必须来自不同厂商、不同 CDN 与不同域名族，避免"同域同时失效"。
产生背景L1 与 L2 同属 binance.vision，该域被封时会一起失效。
结论L3 选用 CoinEx（实测直连 440ms 可用），与 Binance 无共同基础设施依赖。
状态已采纳
关联概念分层容错

健康检查器 (Source Health Monitor)

定义监控数据流活性的组件：5 秒无 tick 判定异常，异常持续 10 秒触发降级；重连采用指数退避；每 5 分钟探测上层源以决定是否回切。
产生背景网络抖动是常态（实测中同一 OKX 接口一次成功一次超时），需要自动而非人工干预。
状态已设计
关联概念分层容错、指数退避

指数退避 (Exponential Backoff)

定义重连间隔随时间倍增：1s → 2s → 4s → 8s → 16s → 30s（封顶）。
产生背景频繁重连会加剧网络负担并耗电，固定短间隔在断网场景下毫无意义。
状态已采纳
关联概念健康检查器

系统代理透传 (System Proxy Inheritance)

定义iOS 上 URLSession / URLSessionWebSocketTask 默认遵循 Wi-Fi 配置中的代理设置（Proxy）与代理类 App（Shadowrocket / Clash / Quantumult X）建立的隧道。
产生背景需判断 App 是否要内置代理配置功能。
结论无需内置代理设置，用户挂上代理工具后自动生效；但探测发现部分技术栈（如 .NET ClientWebSocket）不自动读取系统代理，做网络诊断时须显式指定代理，否则会误判为"直连可用/不可用"。
状态已确认并已修正探测方法
关联概念SNI 阻断、DNS 污染

三、构建与分发类概念

侧载 (Sideloading)

定义不经过 App Store，用个人开发者证书把自编译的 App 直接签名安装到自己的设备上。
产生背景用户无付费开发者账号，无法使用 TestFlight 或 Ad-Hoc 分发。
工具Sideloadly（Windows，USB 安装）、AltStore（半自动续签）
状态已采纳
关联概念免费个人团队、7 天重签、无 Mac 开发链路

免费个人团队 (Free Personal Team)

定义使用免费 Apple ID 在 Xcode 中生成的开发者团队（Personal Team），可进行真机调试与侧载签名。
限制证书 7 天过期；同时最多 3 个侧载 App；无推送（APNs）、无 App Groups、无法上架或分发。
与本项目关系PiP 不需要任何付费权限（entitlement），因此免费账号足以支撑本项目的核心能力。
状态已采纳（待 M0 实机验证）
关联概念侧载、7 天重签、灵动岛

7 天重签 (Weekly Re-signing)

定义免费证书 7 天过期后，App 无法启动，需重新签名安装。
产生背景免费个人团队的平台限制。
应对手动重装（约 1–2 分钟）或 AltStore 自动续签（auto-refresh，要求 PC 与手机同 Wi-Fi 且 AltServer 常驻）。
状态已接受作为零成本方案的代价
关联概念免费个人团队、侧载

文本化工程定义 (XcodeGen)

定义用 project.yml（纯文本）声明 Xcode 工程，构建时由工具生成 .xcodeproj。
产生背景.xcodeproj 是二进制式工程文件，在 Windows 上无法安全编辑；而本项目全程在 Windows 上开发。
收益工程配置可版本化、可代码评审、无二进制冲突。
状态已采纳
关联概念无 Mac 开发链路

无 Mac 开发链路 (Mac-less Build Pipeline)

定义Windows 写码 → GitHub Actions（macOS runner）构建并打包未签名 ipa → Windows 侧载到 iPhone 的完整闭环。
产生背景用户无 Mac、无付费账号，要求零硬件成本。
代价无断点调试器，仅能靠日志排错；单次迭代 3–6 分钟；私有仓库 macOS 构建额度约 200 分钟/月。
状态已采纳（M0 为风险闸门）
关联概念侧载、XcodeGen、风险闸门

风险闸门 (Risk Gate)

定义在投入大量开发前，先验证高风险假设的里程碑节点；未通过则需重新评估整体方案。
产生背景零成本路径的两个致命假设：①免费账号能侧载 ②免费账号下 PiP 可用。
本项目闸门M0（侧载链路打通）与 M1（PiP 悬浮成功）
状态已定义
关联概念无 Mac 开发链路

四、渲染与交互类概念

等宽数字防抖 (Monospaced Digit Layout Stability)

定义价格数字使用等宽字体（monospaced digits），使每次刷新时字符宽度一致，避免整行布局抖动。
产生背景比例字体下 "1" 与 "8" 宽度不同，价格跳动时数字会左右滑动，观感很差。
状态已采纳
关联概念帧泵、帧渲染器

伪直播流 (Fake Live Stream)

定义让 PiP 时间轴返回 .positiveInfinity（无限时长），使系统把内容判定为直播流，从而隐藏进度条与跳转控件。
产生背景行情条不是"可拖动的视频"，但 PiP 默认按视频语义提供播放控制。
状态已设计
关联概念画中画悬浮窗、帧源层

会话保活 (Session Keep-alive)

定义通过 AVAudioSession 设为 .playback 并激活，维持 PiP 会话在后台存活，从而持续刷新价格。
产生背景若不保活，App 进入后台后 PiP 会话会被回收，价格停止更新。
状态已设计
关联概念帧泵、画中画悬浮窗

迟滞触发 (Hysteresis)

定义为「阈值型事件」加上回差：不仅要「进入阈值区」才触发，还要求触发后必须真正离开（离开距离大于触发带宽）才允许下一次触发。
产生背景价格报警最初只考虑「进入 ±容差带即报警」。但 BTC 在阈值附近来回穿越时，这会导致每几秒报一次，功能等于不可用。
现象特征「阈值附近反复触发」——数值在阈值上下抖动时用户被连环轰炸。
状态已采纳：ARMED → ALERTING → COOLDOWN，其中解除冷却需同时满足「冷却时间到」与「价格离开 ±容差×2」

代码合成音 (Runtime Audio Synthesis)

定义不携带音频素材文件，而在运行时用代码生成 PCM 波形，再拼装标准容器（如 44 字节 WAV 头）交给播放器。
产生背景报警音要求「辨识度高」。本项目由 CI 构建，仓库不宜携带二进制素材，且音色需要与手机自带通知音区分开。
关键细节方波（sin(...) >= 0 ? 1 : -1）谐波丰富、穿透力远强于正弦波；起落段加包络消除开关爆音。
状态已采纳：2200Hz 三连方波，AVAudioPlayer 循环播放

闪烁频率安全阈值 (Photo-sensitivity Threshold)

定义闪烁/闪动内容的频率落在 3~30 Hz 区间时，对光敏性癫痫人群存在诱发风险。
产生背景报警需要文字颜色闪烁。直觉上越快越醒目，但越快越危险 —— 这是一个容易被忽略的无障碍约束。
本项目取值2 Hz（半周期 0.25 秒），刻意压在 3 Hz 以下；配合报警期间 8 fps 出帧，恰好每相位 2 帧，交替干净不抖动。
状态已采纳为设计约束

五、实测踩坑与经验（Pitfalls & Lessons）

本节概念全部来自 M1 阶段真实调试过程，是"日志与状态全部正常、画面却全黑/功能却静默失败"这类问题的根因记录， 价值高于任何文档抄写。后续改动 PiP 相关代码时，必须先读本节。

IOSurface 支撑 (IOSurface-backed Pixel Buffer)

定义创建 CVPixelBuffer 时附带 kCVPixelBufferIOSurfacePropertiesKey，使缓冲由 IOSurface（跨进程共享的图形内存表面）支撑。
产生背景AVSampleBufferDisplayLayer 走硬件合成管线，帧缓冲需为 IOSurface 支撑。缺少该属性时，帧能成功入队、图层 status 显示 .rendering、renderSize 回调正常，但画面永远纯黑。
现象特征"所有诊断指标都正常、唯独屏幕全黑"。本项目为此连续排查了 6 轮 CI 迭代才定位。
状态已采纳为必填属性
关联概念帧源层、图层时间基、首像素诊断

图层时间基 (Layer Control Timebase)

定义驱动 AVSampleBufferDisplayLayer 决定"某帧何时显示"的时间基准对象 CMTimebase，通过 controlTimebase 属性设置。
产生背景实测发现图层的 controlTimebase 默认是 nil（并非文档暗示的自动创建）。没有时间基准时，帧无法判定显示时刻，全部滞留不显示。
API 陷阱CMTimebaseCreateWithSourceClock(allocator:sourceClock:timebaseOut:) 的形态是"输出参数 + 返回 OSStatus"，而非常见的"直接返回对象"。凭记忆书写连续编译失败三次。
状态已采纳：启动时显式创建并设 rate=1.0，帧 PTS 取该时间基当前时间
关联概念伪直播流、IOSurface 支撑

立即显示附件 (DisplayImmediately Attachment)

定义样本缓冲上的 attachment：kCMSampleAttachmentKey_DisplayImmediately，含义为"这一帧立即显示，不要等待时间戳到期"。
产生背景直播式内容的 PTS 与系统时钟基准不一定严格对齐，缺少该附件时帧可能被搁置。
状态已采纳
关联概念图层时间基、帧源层

宿主容器约束 (Host Container Constraint)

定义承载显示层的容器视图必须保持 1×1 尺寸，图层自身尺寸取画面尺寸（640×200）。
产生背景实测：把容器换成 320×100 的可见视图后，startPictureInPicture() 会静默失败——willStart、didStart、failedToStart 三个回调一个都不触发，而 isPictureInPicturePossible 却返回 true。
状态已确认（两轮独立对照验证）
关联概念画中画悬浮窗、IOSurface 支撑

构建指纹 (Build Fingerprint)

定义CI 构建时把 commit SHA 与构建时间写入源码常量，App 界面直接显示，用于确认设备上安装的究竟是哪一版。
产生背景调试期间曾因重复安装旧 ipa，导致新修复未被验证、白跑一轮排查。
状态已采纳（界面「构建提交」一行）
关联概念无 Mac 开发链路、侧载

单变量对照原则 (One-variable-at-a-time)

定义排查问题时每次只改动一个变量，否则无法判定哪个改动真正起作用。
产生背景M1 调试中曾同时改动"容器尺寸 + 像素缓冲属性"，结果把"A+B 一起改好了"错记成"A 是关键"，导致后续基于错误结论连锁走了两条弯路（因果倒置两次）。
状态已确立为项目排查纪律
关联概念构建指纹、无 Mac 开发链路（迭代成本高，更需纪律）
