悬浮行情 App（BTC · iOS）设计文档

项目代号 FloatingTicker ｜ 版本 v1.2 ｜ 日期 2026-09-17 ｜ 主力机 iPhone 17 Pro Max ／ 测试机 iPhone 17（均 iOS 26），最低支持 iOS 17 ｜ 形态：画中画悬浮行情条

一句话定义：在 iPhone 上实现一个可悬浮于任意 App 之上的实时 BTC 行情条，采用 iOS 画中画（Picture-in-Picture, PiP）技术，全程无需 Mac 本地环境，零硬件成本完成开发与自用部署。

1. 项目概述

1.1 目标（Goals）

  • 目标设备：主力机 iPhone 17 Pro Max（最终长期使用），测试机 iPhone 17（承担全部试验性验证）。两台均运行 iOS 26；工程部署目标设为 iOS 17.0，保留向下兼容能力
  • 在任意 App 之上显示实时 BTC 价格（悬浮窗 floating overlay）
  • 价格 1Hz 级别刷新，肉眼体验为实时
  • 国内网络直连可用（无需翻墙），并能自动切换到兜底源
  • 零硬件成本：不购买 Mac，不购买 Apple 开发者付费账号

两台设备同代、同系统版本（iOS 26）、同架构（arm64），因此在测试机上验证通过的结论可直接迁移到主力机，不存在机型差异风险；两台均具备灵动岛，第二版若引入实时活动（Live Activity）也无需区分机型。

设备角色分工（重要）：所有高风险验证（侧载链路打通、PiP 可用性探测、反复失败的构建试验）一律先在测试机 iPhone 17 上做；主力机 iPhone 17 Pro Max 只在验证通过后安装稳定版本。理由有二：① 免费账号的设备注册名额有限且消耗后不易回收，主力机的名额只用于装确定可用的版本；② 试验阶段的签名失败、证书反复更换、App 崩溃等现象不干扰主力机的日常使用。

1.2 非目标（Non-Goals）

  • 不做 K 线图、盘口、下单等交易功能
  • 不做多币种（仅 BTC）
  • 不做 Android 版本
  • 第一版不做灵动岛 / 实时活动（Live Activity）
  • 不做 App Store 上架、不做多用户分发

1.3 必须接受的平台事实（Platform Constraints）

iOS 禁止第三方 App 在其他 App 之上绘制任意视图。没有 Android 那种系统级悬浮窗权限（SYSTEM_ALERT_WINDOW）。

唯一合法途径是画中画：系统托管的悬浮视频窗口，可置顶于桌面与任意 App 之上。

因此本项目本质是：把行情数据渲染成"视频帧"，用 PiP 播放。

2. 核心技术决策

决策项选择理由被否方案
悬浮实现方式画中画 PiPiOS 唯一合法的全局悬浮能力小组件（不能悬浮、刷新受限）、灵动岛（区域太小）

开发语言纯 Swift + SwiftUIPiP 本身就是原生代码，语言层越薄越好React Native（多一层桥接与构建复杂度，零收益）

核心发现：Binance 的公共数据域（*.binance.vision，走 AWS CloudFront）在国内直连可达且高度稳定，无需任何代理即可获得 1Hz 实时 BTC 价格。这解决了"稳定兜底"的核心诉求。

4.2 分层容错设计（Failover Layers）

层级数据源传输方式启用条件刷新频率
L1Binance 公共数据域WebSocket 推送默认1Hz（服务端推送）
L2Binance 公共数据域REST 轮询L1 握手失败2s
L3CoinExREST 轮询L2 连续失败 2 次
（异构厂商，抵御单域封禁）		2s
L4OKXWS / REST用户手动开启（代理环境）1Hz
L5自建中继（VPS 反代）WebSocket可选，人工配置1Hz

4.3 健康检查与切换策略（Health Monitor）

项策略
心跳超时5 秒无 tick 判定异常
降级触发异常持续 10 秒 → 切换下一层
重连退避指数退避（exponential backoff）：1s → 2s → 4s → 8s → 16s → 30s 封顶
恢复策略切到某层成功后，每 5 分钟探测上一层，可用则回切（prefer-higher-tier）
可观测性App 内显示当前数据源、最近延迟、切换日志

选型注意：L1 与 L2 同域，同域封禁时会同时失效，因此 L3 必须是异构（不同厂商、不同 CDN）的源才具兜底价值。

4.4 抽象设计（Pluggable）

protocol MarketDataSource {
    var name: String { get }
    var tier: Int { get }                       // 优先级层级
    func start()
    func stop()
    var onTick: ((TickerSnapshot) -> Void)? { get set }
    var onStateChange: ((SourceState) -> Void)? { get set }
}

struct TickerSnapshot {
    let symbol: String        // BTCUSDT
    let last: Double          // 最新价
    let changePercent: Double // 24h 涨跌幅
    let updatedAt: Date
}

所有源实现同一协议，MarketStore 只依赖协议，切换源不影响上层渲染。

5. PiP 渲染管线

MarketStore（行情状态聚合）
      ↓ 价格变化通知
FramePump（帧泵，自适应帧率）
      · 价格变化 → 立即出帧
      · 静止状态 → 1 fps 心跳保活（keep-alive）
      ↓
TickerFrameRenderer（CoreGraphics 绘制 → CVPixelBuffer）
      · 币对名 · 最新价（等宽数字，避免宽度抖动）
      · 涨跌幅标签（绿涨红跌）
      ↓
SampleBufferFactory（CVPixelBuffer → CMSampleBuffer）
      ↓
AVSampleBufferDisplayLayer
      ↓
AVPictureInPictureController → 系统悬浮窗

5.1 关键实现点

要点做法原因
会话保活AVAudioSession 设为 .playback 并 setActive(true)PiP 会话在后台存活、持续刷新价格的前提
内容源ContentSource(sampleBufferDisplayLayer:playbackDelegate:)iOS 15+ 的自定义帧源接口
伪装直播流时间轴返回 .positiveInfinity隐藏进度条，只保留播放/关闭控件
画面比例由 CVPixelBuffer 尺寸决定（如 640×200）还原"长条"悬浮条观感
回到 App实现 restoreUserInterfaceForPictureInPictureStop用户点击"还原"时正确切回前台
数字防抖使用等宽数字（monospaced digits）价格跳动时不产生布局抖动
省电价格未变化时降到 1 fps帧泵是持续耗电点
后台模式Info.plist 声明 UIBackgroundModes: audioPiP 会话后台存活
像素缓冲必须由 IOSurface 支撑（kCVPixelBufferIOSurfacePropertiesKey）图层走硬件合成管线；缺少该属性时帧能入队、状态显示 .rendering，却永远全黑——本项目实测踩过此坑（第 13 章）
时间基显式创建并设置 controlTimebase，帧 PTS 取该时间基的当前时间图层默认没有时间基（实测为 nil），帧无法判定显示时刻。创建接口为 CMTimebaseCreateWithSourceClock(allocator:sourceClock:timebaseOut:)（输出参数 + OSStatus 返回）
宿主容器容器视图保持 1×1，显示层尺寸用画面尺寸实测换成可见大容器后 startPictureInPicture() 会静默失败（无任何回调）
立即显示样本缓冲带 kCMSampleAttachmentKey_DisplayImmediately直播式内容需强制立即出画，不等时间戳
播放控制sample buffer 模式下系统会禁用快进/快退控制与"伪直播流"设计方向一致，无需额外处理；目标系统 iOS 26 下该组合仍为 Apple 官方支持的内容源

7. CI 流水线

name: ios-build
on:
  push:
    branches: [ main ]
  workflow_dispatch:

jobs:
  build:
    runs-on: macos-15
    steps:
      - uses: actions/checkout@v4
      - name: Install XcodeGen
        run: brew install xcodegen
      - name: Generate Xcode project
        run: xcodegen generate
      - name: Build (unsigned)
        run: |
          xcodebuild build \
            -project FloatingTicker.xcodeproj \
            -scheme FloatingTicker \
            -sdk iphoneos \
            -configuration Release \
            CODE_SIGNING_ALLOWED=NO \
            CODE_SIGNING_REQUIRED=NO \
            CODE_SIGN_IDENTITY="" \
            CONFIGURATION_BUILD_DIR=$PWD/build
      - name: Package ipa
        run: |
          mkdir -p Payload
          cp -R build/FloatingTicker.app Payload/
          zip -qr FloatingTicker-unsigned.ipa Payload
      # 产物自检：CI 报成功不等于 ipa 可安装，校验不通过则构建失败
      - name: Verify ipa contents
        run: |
          rm -rf verify && mkdir verify
          unzip -q FloatingTicker-unsigned.ipa -d verify
          APP_BIN=verify/Payload/FloatingTicker.app/FloatingTicker
          test -f "$APP_BIN"
          # 用类型判定而非体积阈值：极小的 App 二进制只有几十 KB，阈值易误报
          case "$(file "$APP_BIN")" in *Mach-O*arm64*) ;; *) exit 1 ;; esac
      - uses: actions/upload-artifact@v4
        with:
          name: FloatingTicker-ipa
          path: FloatingTicker-unsigned.ipa

8. 侧载与续签流程

8.1 首次安装

安装顺序：先测试机，后主力机。以下步骤先在测试机 iPhone 17 上完整走一遍，确认 App 能启动、PiP 正常，再对主力机 iPhone 17 Pro Max 重复一次。

  1. Windows 安装 Apple 官方 iTunes（提供 Apple 设备驱动，不要用微软商店版）
  2. 下载 FloatingTicker-unsigned.ipa（CI artifact）
  3. Sideloadly 打开 ipa，输入免费 Apple ID，USB 连接 iPhone，开始签名安装
  4. iPhone 上：设置 → 通用 → VPN 与设备管理 → 信任该开发者证书
  5. 设置 → 通用 → 关于本机 → 证书信任设置（如出现提示）
  6. 运行 App，点击"开启悬浮窗"，然后切到桌面查看 PiP 窗口

8.2 免费账号限制

限制影响应对
证书 7 天过期到期后 App 无法启动每周重新侧载；或使用 AltStore 自动续签
同时最多 3 个侧载 App需要删掉不用的只保留本项目
无推送权限（APNs）无法后台刷新本版不使用（PiP 不需要）
设备注册数量上限免费账号可绑定的设备数有限（业内普遍引用为 3 台，需实测确认）两台 iPhone 通常够用；Sideloadly 注册设备时会给出明确提示
无法上架 / 分发仅自己可用符合自用定位

方案自动化程度要求推荐度
